## Web push notifications for the morning/evening briefing

**Raised:** 2026-05-01 (evening)
**Phase context:** Acceptance criterion #10 — Doc 04 §5.
**Owner:** Claude (next session)
**Decide-by:** Before declaring Phase 1 sign-off complete.

The briefing cron runs (when Redis is up) but currently only writes to DB — no push to Selmen's device. Spec asks for web push with SMS fallback when the PWA hasn't been opened recently. Implementation is non-trivial:
- Generate VAPID keys, store as `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` env vars
- Add `web-push` server lib, add `/api/push/subscribe` + `/api/push/unsubscribe` endpoints
- Update PWA service worker (`vite-plugin-pwa` config) with a `push` event handler
- Add a "Enable notifications" prompt in PWA settings or first-time-use flow
- Wire the briefing cron's `generateBriefingForDate` to fan-out a push to all subscribed clients
- SMS fallback if no client has connected in the last 4h

Plan as a focused feature PR after Phase 1 publish-and-soak.

## A2P 10DLC registration for the Twilio agent number

**Raised:** 2026-05-01 (evening)
**Phase context:** Phase 2 blocker (outbound SMS).
**Owner:** Selmen
**Decide-by:** Before Phase 2 dispatch ships.

Twilio surfaced the warning when configuring the number: *"A2P 10DLC registration required for US messaging."* Without it, US carriers will filter or throttle outbound SMS to your team. **Inbound (you → agent) works without registration**, so Phase 1 testing is unblocked.

Initiate via Twilio Console → Regulatory Compliance → A2P 10DLC. Approval can take 1–2 weeks.
